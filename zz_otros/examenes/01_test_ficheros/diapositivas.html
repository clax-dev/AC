1 · Conceptos básicos

¿Por qué ficheros? Texto frente a binario

  • Las variables viven en la memoria RAM, que se borra cuando termina el programa.
  • Un fichero está en el disco y conserva los datos aunque se apague el ordenador. Es la forma más básica de persistencia.
  • Una carpeta o directorio no guarda datos: solo agrupa ficheros y otras carpetas.
  • Por dentro, todo fichero son bytes (valores de 0 a 255).
Fichero de textoFichero binario
Los bytes son…letras (caracteres)datos en bruto
Bloc de notasse leesímbolos raros
Ejemplos.txt .csv .log .properties.dat .bin .ser .jpg .xlsx
Clases JavaReader / WriterInputStream / OutputStream
Ventajalegible por personasocupa menos, más rápido

Ejemplo: el número 2000000 como texto ocupa 7 caracteres; como int binario ocupa siempre 4 bytes.

Idea clave: texto = bytes que representan letras; binario = bytes que representan datos. Los dos son bytes.

2 · Rutas

Una ruta NO es el fichero

  • Una ruta es la dirección de un fichero o carpeta. En Java es un objeto Path (moderno, java.nio.file) o File (antiguo, java.io).
  • Crear un Path no toca el disco: no crea nada y no falla aunque el fichero no exista.
  • El disco se toca al usar Files: createDirectories, write, move… y eso sí puede lanzar IOException.
  • Path es inmutable: resolve, normalize y toAbsolutePath devuelven una ruta nueva que hay que guardar.
Path carpeta = Paths.get("salida", "config"); // = Path.of(...)
Path fichero = carpeta.resolve("app.properties");
fichero.getFileName();     // app.properties
fichero.getParent();       // salida/config
fichero.toAbsolutePath();  // C:\...\salida\config\app.properties
Paths.get("a/b/../c").normalize();  // a/c
Absoluta: desde la unidad (C:/DAM/...).
Relativa: ("datos/mapa.dat") se completa con el directorio de trabajo, la carpeta desde la que se ejecuta el programa.
Idea clave: escribir la dirección en el sobre no construye la casa. Si «no encuentra el fichero», imprime toAbsolutePath().

4 · Operaciones con carpetas y ficheros

Crear, mover, copiar y borrar

  • createDirectory(p): crea una carpeta; falla si no existe la carpeta padre o si ya existe.
  • createDirectories(p): crea toda la cadena; no falla si ya existe. Es la forma segura.
  • createFile(p): crea un fichero vacío; falla si ya existe.
  • Mover y renombrar son la misma operación (Files.move / renameTo): ambas cambian la dirección.
  • En el mismo disco, mover es instantáneo: no copia datos.
  • Una carpeta solo se borra si está vacía → si no, DirectoryNotEmptyException.
  • delete(p) lanza NoSuchFileException si no existe; deleteIfExists(p) devuelve false.
Files.move(DESDE, HASTA, StandardCopyOption.REPLACE_EXISTING);
Files.copy(origen, copia, StandardCopyOption.REPLACE_EXISTING);
Trampas de move/copy:
• El orden es move(origen, destino).
• El destino es la ruta completa con el nombre: .../ejercicios/carpeta, no .../ejercicios.
• La carpeta de destino tiene que existir.
• Si el destino existe y no pasas REPLACE_EXISTING → FileAlreadyExistsException.
• En Windows no se puede mover un fichero abierto.
Idea clave: mover = cambiar la dirección; el destino lleva el nombre final y su carpeta debe existir.

4 · Listar carpetas

Listar y recursividad

  • File.listFiles() y Files.list(p) devuelven solo el primer nivel de la carpeta.
  • Para recorrer todas las subcarpetas se usa recursividad: si un elemento es carpeta, el método se llama a sí mismo con ella.
  • El caso base es llegar a una carpeta sin subcarpetas: ahí la recursión termina sola.
  • Alternativa NIO: Files.walk(p) recorre todos los niveles.
  • Files.list y Files.walk devuelven un Stream que deja la carpeta abierta: van en try-with-resources.
static void listar(File carpeta, int nivel) {
    for (File h : carpeta.listFiles()) {
        String sangria = "  ".repeat(nivel);
        if (h.isDirectory()) {
            System.out.println(sangria + "[DIR] " + h.getName());
            listar(h, nivel + 1);      // recursividad
        } else {
            System.out.println(sangria + "[FILE] " + h.getName());
        }
    }
}

try (Stream<Path> s = Files.list(carpeta)) {
    s.forEach(p -> System.out.println(p.getFileName()));
}
Idea clave: listar = un nivel; para todos los niveles, recursividad (o Files.walk).

5 · Leer y escribir

Abrir, usar, cerrar: try-with-resources

  • Toda lectura o escritura: abrir → usar → cerrar.
  • Al escribir, Java acumula los datos en un búfer (memoria) y los manda al disco por bloques. Cerrar vacía el búfer. Sin cerrar, lo último escrito puede no llegar al disco.
  • Un fichero abierto queda bloqueado por el sistema (en Windows no se puede borrar ni mover).
  • try-with-resources: el recurso declarado en los paréntesis del try se cierra automáticamente al salir, haya excepción o no. Funciona con cualquier clase que implemente AutoCloseable.
  • Se pueden abrir varios recursos en el mismo try, separados por ;.
try (BufferedWriter bw = Files.newBufferedWriter(p)) {
    bw.write("línea 1");
    bw.newLine();
}   // aquí se cierra solo

try (InputStream in = Files.newInputStream(a);
     OutputStream out = Files.newOutputStream(b)) {
    in.transferTo(out);
}
Idea clave: lo que se abre va en try ( ) y se cierra solo. Sin cerrar, el búfer no llega al disco.

}

8 · Seguridad

Path Traversal

  • Ataque en el que el usuario mete .. («subir una carpeta») en una ruta para salirse de la carpeta permitida.
  • datos/../../etc/passwd empieza por «datos», pero sube dos niveles y acaba fuera.
  • Defensa:
    1. Pasar las dos rutas (base y la del usuario) a toAbsolutePath() y después normalize(), que resuelve los ...
    2. Comprobar con Path.startsWith(base).
    3. Si no empieza por la base: SecurityException.
  • Path.startsWith compara carpeta a carpeta; String.startsWith compara letra a letra y deja pasar "datos2/secreto.txt" como si estuviera en "datos".
Path base = Paths.get("datos").toAbsolutePath().normalize();
Path cand = Paths.get(rutaUsuario).toAbsolutePath().normalize();
if (!cand.startsWith(base)) {
    throw new SecurityException("Fuera de datos/: " + rutaUsuario);
}
RutaResultado
datos/informe.csvdentro
datos/../../etc/passwdfuera
datos/sub/../informe.csvdentro
datos2/secreto.txtfuera (con Path)
Idea clave: normaliza las dos rutas y compara carpeta a carpeta, nunca letra a letra.

10 · Guardar objetos (1)

CSV: objetos como líneas de texto

  • CSV: una línea por objeto, campos separados por ; o ,. La primera línea es la cabecera.
  • Guardar (objeto → línea): String.join(";", campos).
  • Cargar (línea → objeto): skip(1) para la cabecera, split(";") y convertir cada trozo: Integer.parseInt, Double.parseDouble.
  • split devuelve String[]: los trozos siguen siendo texto.
  • Double.parseDouble("25,90") → NumberFormatException: Java usa punto. Al escribir: String.format(Locale.ROOT, "%.2f", x).
  • Ventaja: legible, lo abre Excel y cualquier lenguaje. Inconveniente: convertir cada campo a mano.
codigo;nombre;precio;stock
P001;Teclado;25.90;12

try (Stream<String> s = Files.lines(csv)) {
    List<Producto> lista = s
        .skip(1)                         // cabecera
        .filter(l -> !l.isBlank())
        .map(l -> {
            String[] c = l.split(";");
            return new Producto(c[0], c[1],
                Double.parseDouble(c[2]),
                Integer.parseInt(c[3]));
        })
        .toList();
}

10 · Guardar objetos (2)

Binario: DataOutputStream y DataInputStream

  • Escriben y leen tipos primitivos en binario: writeInt, writeDouble, writeUTF, writeBoolean… / readInt, readDouble, readUTF…
  • El fichero no tiene etiquetas: solo bytes seguidos.
  • Regla de oro: leer en el mismo orden y con los mismos tipos con que se escribió. Si no, no hay error: salen valores sin sentido.
  • Fin del fichero: no devuelve null ni -1; lanza EOFException.
  • Se suelen envolver: DataOutputStream(BufferedOutputStream(FileOutputStream)). Abrir un OutputStream vacía el fichero.
  • InputStream.read(byte[]) devuelve -1 al final (es distinto de readInt).
TipoBytes
byte, boolean1
short, char2
int, float4
long, double8
String con writeUTF2 (longitud) + bytes del texto
try (DataInputStream in = new DataInputStream(
        new FileInputStream("productos.dat"))) {
    while (true) {
        String cod = in.readUTF();
        double pre = in.readDouble();
        int stock = in.readInt();
    }
} catch (EOFException fin) { /* fin normal */ }

10 · Guardar objetos (3)

Serialización: ObjectOutputStream y ObjectInputStream

  • Serializar = convertir un objeto entero en bytes. Deserializar = reconstruirlo.
  • writeObject(obj) / readObject(). Se puede guardar una lista entera de una vez.
  • La clase debe implements Serializable: interfaz marcadora, sin métodos. Si no → NotSerializableException.
  • Sus atributos también deben ser serializables.
  • serialVersionUID: número de versión de la clase. Si no coincide con el del fichero → InvalidClassException.
  • transient: el atributo no se guarda; al leer vale null, 0 o false. Uso: contraseñas.
  • readObject() devuelve Object → hace falta cast. Puede lanzar ClassNotFoundException.
  • Solo lo entiende Java.
class Usuario implements Serializable {
    private static final long serialVersionUID = 1L;
    String nombre;
    transient String password;   // no se guarda
}

try (ObjectOutputStream out = new ObjectOutputStream(
        Files.newOutputStream(f))) {
    out.writeObject(lista);
}
try (ObjectInputStream in = new ObjectInputStream(
        Files.newInputStream(f))) {
    List<Usuario> l = (List<Usuario>) in.readObject();
}

Acceso aleatorio: RandomAccessFile

  • Acceso secuencial: para llegar al registro 1000 hay que leer los 999 anteriores (como una cinta).
  • Acceso aleatorio o directo: se salta a cualquier posición con seek(pos) (como un array).
  • Requisito: registros de tamaño fijo. Posición del registro n (empezando en 0) = n × tamaño del registro.
  • Los textos se rellenan con espacios hasta un tamaño fijo. writeChars usa 2 bytes por carácter.
  • Modos: "r" (leer) y "rw" (leer y escribir).
  • Métodos: seek, getFilePointer, length, setLength + los readXxx/writeXxx de Data*Stream.
  • Escribir sobrescribe (no inserta). Ventaja: modificar un solo registro sin reescribir el fichero.
  • Número de registros = length() / TAM.
CampoTipoBytesDesde
idint40
nombre20 chars404
preciodouble844
stockint452
TOTAL56
try (RandomAccessFile raf =
        new RandomAccessFile("prod.dat", "rw")) {
    raf.seek(2L * 56);            // registro 2
    int id = raf.readInt();
    raf.seek(1L * 56 + 52);       // stock del registro 1
    raf.writeInt(50);
}

11 · NIO

ByteBuffer y FileChannel

  • FileChannel (java.nio.channels): la conexión con el fichero, como una tubería. Lee y escribe en la posición que elijas.
  • ByteBuffer (java.nio): una caja de bytes en memoria de tamaño fijo. Se llena con putInt, put(byte[])… y se vacía con getInt, getLong…
  • Tres marcas: position (cursor), limit (hasta dónde) y capacity (tamaño total).
  • flip(): limit = position y position = 0. Pasa de modo llenar a modo vaciar. Sin flip no se escribe nada.
  • write puede no escribirlo todo: while (buffer.hasRemaining()).
  • canal.read(buf) devuelve -1 al final.
  • ByteBuffer.wrap(Files.readAllBytes(p)): caja ya llena y lista para leer, sin canal ni flip.
try (FileChannel canal = FileChannel.open(ruta,
        StandardOpenOption.CREATE, StandardOpenOption.WRITE)) {
    ByteBuffer b = ByteBuffer.allocate(44);
    b.putInt(101);                               // 4 bytes
    b.put(Arrays.copyOf("SSD 1TB".getBytes(
            StandardCharsets.UTF_8), 40));       // 40 bytes
    b.flip();
    while (b.hasRemaining()) {
        canal.write(b);
    }
}
// modificar en una posición concreta
canal.write(ByteBuffer.wrap(nuevo), n * 44L + 4);
Trampas: getShort() tiene signo (0xCAFE sale negativo → Short.toUnsignedInt). Olvidar flip() → BufferUnderflowException. ByteBuffer no tiene getUTF.

12 · Excel

Apache POI

  • Java no sabe crear .xlsx solo: se usa la librería externa Apache POI (org.apache.poi:poi-ooxml, dependencia Maven).
  • Jerarquía: XSSFWorkbook (libro) → Sheet (hoja) → Row (fila) → Cell (celda).
  • Filas y celdas se numeran desde 0: createRow(0) es la fila 1 y createCell(0) la columna A.
  • Valores: setCellValue(texto o número). Guarda los números como número para que Excel opere.
  • Fórmulas: setCellFormula("B2*C2"), sin el signo =.
  • Estilo: CellStyle + Font (setBold(true)), creado desde el libro y aplicado con setCellStyle.
  • autoSizeColumn(i) ajusta el ancho. libro.write(out) guarda.
  • HSSFWorkbook es para el formato antiguo .xls.
try (XSSFWorkbook libro = new XSSFWorkbook();
     OutputStream out = Files.newOutputStream(ruta)) {
    Sheet hoja = libro.createSheet("Inventario");
    Row fila = hoja.createRow(1);
    fila.createCell(0).setCellValue("SSD 1TB");
    fila.createCell(1).setCellValue(89.90);
    fila.createCell(2).setCellValue(3);
    fila.createCell(3).setCellFormula("B2*C2");
    hoja.autoSizeColumn(0);
    libro.write(out);
}
