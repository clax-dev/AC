📋ResultSetLas filas de respuesta: se leen una a una con next()
try (Connection con = DriverManager.getConnection(URL, USER, PASS);
     PreparedStatement ps = con.prepareStatement(
         "SELECT id, nombre FROM producto WHERE precio > ?")) {
    ps.setDouble(1, 10.0);              // ⚠ el primer ? es el 1
    try (ResultSet rs = ps.executeQuery()) {
        while (rs.next()) {               // avanza a la siguiente fila
            int id = rs.getInt("id");
            String n = rs.getString("nombre");
        }
    }
}   // se cierra todo solo (tema 4: lo que se abre, se cierra)

2 · SEGURIDAD Y TRANSACCIONES

Huecos, no pegamento · Todo o nada

💉 Inyección SQL: concatenarSi el usuario escribe ' OR '1'='1, entra sin contraseña.
// ❌ el texto del usuario pasa a ser SQL
String sql = "SELECT * FROM usuario WHERE nombre = '"
        + nombre + "'";
Statement st = con.createStatement();
st.executeQuery(sql);
✅ PreparedStatementEl valor va en un hueco ? y se trata siempre como dato, nunca como SQL.
PreparedStatement ps = con.prepareStatement(
    "SELECT * FROM usuario WHERE nombre = ?");
ps.setString(1, nombre);
🏦 Transacción: todo o nadaUna transferencia son dos UPDATE: restar en una cuenta y sumar en otra. Si falla el segundo, el primero se deshace.
con.setAutoCommit(false);    // empiezo la transacción
try {
    restar.executeUpdate();
    sumar.executeUpdate();
    con.commit();               // ✅ se guardan las dos
} catch (SQLException e) {
    con.rollback();             // ↩ no se guarda ninguna
}
Por defectoautocommit: cada sentencia se guarda sola
ExcepciónSQLException (checked, como IOException)
«Nunca pegues texto del usuario en el SQL: usa ?.» · «Varias operaciones que van juntas, en una transacción: o todas o ninguna.»

3 · JPA / HIBERNATE

La clase es la tabla

@Entity                          // esta clase es una tabla
@Table(name = "producto")
public class Producto {
    @Id                          // la clave primaria
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;              // la pone la BD (autoincrement)

    @Column(nullable = false)
    private String nombre;
    private double precio;

    public Producto() { }         // ⚠ obligatorio (como en Jackson)
    // getters y setters
}
JavaBase de datos
clase @Entitytabla
atributocolumna
un objetouna fila
@Idclave primaria
EntityManager: el que habla con la BD persist(p) guarda (INSERT)
find(Producto.class, id) busca por id (SELECT)
merge(p) actualiza (UPDATE)
remove(p) borra (DELETE)
Los cambios van entre getTransaction().begin() y commit().
JPQL: consultas sobre clases SELECT p FROM Producto p WHERE p.precio > :min
Se pregunta por la clase y sus atributos, no por la tabla. :min es un hueco con nombre.
Configuración persistence.xml (en resources/META-INF): URL, usuario, contraseña y driver.
Hibernate 6: anotaciones en jakarta.persistence (antes javax).
«Con JPA no escribes el SQL: anotas la clase y Hibernate traduce cada objeto en una fila.» Es la idea de Jackson (objeto ↔ JSON), pero objeto ↔ tabla.

JDBC si…consultas concretas, informes, pocos datos o quieres control total del SQL.
JPA si…una aplicación con muchas entidades y CRUD (crear, leer, actualizar, borrar).
En la empresaSpring Boot usa JPA/Hibernate por defecto (Spring Data JPA).
Las dos llegan al mismo sitio: JPA escribe el SQL por ti y por debajo lo manda con JDBC.
